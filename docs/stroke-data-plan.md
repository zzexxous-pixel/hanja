# 대한검정회 자형·획순 대조 및 예외 데이터 계획

상태: 2026-10-30 구현 시작. 예외 manifest/공통 resolver/정적 SVG/敬13획 및 기본 누락16자 보완 구현. 대한검정회 전체 자형·획순 검수는 미완료. 현재 현황은 glyph-audit.md 참조.

## 현재 구현과 사용 방법
- data/stroke-overrides/manifest.json에 글자별 고정 SVG 원본·SHA256·예상 획수·부수·근거·검수 상태 등록.
- sources/에 라이선스가 명시된 원본 SVG를 보관한다. 새 예외도 같은 구조로 추가한다.
- scripts/strokes.mjs에서 원본 체크섬 검증 → 좌표 변환/중심선 표본화 → 쓰기 JSON과 카드 SVG를 함께 생성.
- 별도 변환 JSON을 소스에 중복 커밋하지 않음. 배포물 assets/strokes/<코드>.json / assets/glyphs/<코드>.svg에 생성.
- strokeData.js가 공통 manifest를 참조하고 실제 글자 요청 때만 JSON을 읽는다. 최대64건 메모리 캐시, 동일 요청 중복 제거, 실패 후 재시도.
- 쓰기 엔진3.7.3/기본 데이터2.0.1 버전 고정. npm에서 설치한 개발 의존성 중 필요한 파일만 자체 제공. 런타임 CDN 의존성 제거.
- 기본 983자 + 敬13획 + 기본 데이터 누락16자 = 지원1,000자 전체 정적 SVG/쓰기 JSON.
- 카드마다 쓰기 엔진을 생성하지 않는다. 50자 단위 기존 DOM 캐시 + lazy SVG img, 접근성 문자 텍스트 유지.
- 敬 획수는 사용자 근거에 맞추었으나 원본의 자형/획순 전부가 대한검정회와 같다는 검수는 대기.
- 기존 아래 계획 중 파일명/흐름은 현재 구현을 우선한다.

## 1. 기본 엔진과 데이터 우선순위
Hanzi Writer 엔진 유지. 기본 글자는 기존 hanzi-writer-data를 사용한다.
한자 문자열(U+코드)을 키로 하는 예외 manifest를 만들고, 검증 완료된 예외만 우선한다.

예정 파일:
- data/stroke-overrides/manifest.json: 한자, 코드포인트, 파일, 출처/고정 commit, 원본 sha256, 라이선스, 예상 획수, 검수 근거, 상태.
- data/stroke-overrides/656C.json: 검수 완료된 敬의 Hanzi Writer 호환 데이터.
- scripts/convert-strokes.mjs: 빌드/관리 시 SVG 윤곽·중심선을 변환. 런타임 변환 금지.
- docs/glyph-audit.md: 기준과 검수 현황.
- 원본 및 대량 비교 자료는 허가·크기 확인 후 외부 artifact 사용; 불필요한 대량 원자료를 Git에 넣지 않는다.

writingEngine.js의 charDataLoader가:
1. enabled 예외 manifest에 있으면 해당 원본으로 변환한 자체 JSON 로딩. 검수 상태는 별도 보존.
2. 없으면 버전 고정된 기본 Hanzi 데이터를 필요 시 로딩.
3. 메모리 캐시/동일 요청 중복 제거.
4. 승인된 13획 예외 로딩 실패 시 임의의 12획 원본으로 조용히 fallback하지 말고 재시도/안내. 오류를 학습 정답처럼 보이지 않게 한다.

## 2. 敬 시제품
사용자 대한검정회 견본=13획. AnimCJK svgsZhHant/25964.svg에 윤곽13개가 있는 것을 확인했지만 대한검정회 전체 순서·방향 일치는 미확인.
svgsKo/25964.svg는 12획이므로 한국어 폴더를 자동 선택하지 않는다.
원본: https://github.com/parsimonhi/animCJK/blob/master/svgsZhHant/25964.svg
고정 commit/라이선스를 기록하고 변환한다. Arphic Public License 조건 검토.
변환 시 각 윤곽과 중심선 매칭, 1024 좌표계/Y축 변환, 시작·끝점, 중복/누락, medians 표본화, 부수 radStrokes 재매핑 필요.
획수 라벨만 13으로 고치거나 기존 획 하나를 임의 분할하는 방식은 금지.
대한검정회 견본은 획수뿐 아니라 실제 획순 자료가 필요하다. 견본의 이미지 저작권과 데이터 재배포 허용 여부 확인.
13획 시연/직접쓰기 성공·오류/완료, 모바일 터치, 부수 배지 검증 후 사용자 시각 승인.

## 3. 전체 1,000자 대조 절차
1. 앱의 실제 지원 한자 전체 목록과 급수/훈음을 추출. 공식 원자료의 발행일·급수·버전/페이지를 연결.
2. 대한검정회 원자료 확보: 공개 자료 URL/파일 또는 사용자 제공 자료. 자동 수집·복제 권한 확인 전 대량 스크래핑하지 않는다.
3. 기준 manifest에 공식 획수/확인 가능한 자형/획순 근거를 입력. 없는 값은 unknown으로 두며 추정값을 공식으로 표시하지 않는다.
4. 기본 데이터 획수와 공식 획수 자동 비교. missing / count-mismatch / shape-review / order-review / approved 분류.
5. 획수가 같아도 자형/순서가 다를 수 있으므로 전 글자 대조표를 작성. 공식 견본, 현재 폰트, 기본 획 SVG를 나란히 보여 주는 검수 페이지(별도 도구)를 생성.
6. 이미지 차이는 후보 정렬에만 활용. 스케일/서체/여백의 차이가 있어 픽셀 차이·OCR·AI 판정만으로 오답 확정하지 않는다.
7. 공통 부품별로 묶어 조사(艹, 辶, 示/礻, 食/飠 등은 조사 후보일 뿐 대한검정회 불일치로 확인된 사례가 아님).
8. 사람이 확인한 불일치만 이슈에 등록하고 한자별 예외 데이터로 해결. 검수자/근거/수정 버전 기록.
9. 모든 글자는 unknown/pending/approved 상태가 있어야 한다. 13획 한 건 확인을 전체 일치로 보고하지 않는다.

## 4. 카드 자형 통일 (후속)
같은 검증된 데이터 resolver에서 카드 정적 SVG와 상세 시연 데이터를 얻는다.
카드마다 Hanzi Writer 인스턴스를 만들지 않고 SVG를 사전 생성한다. 50자 단위 렌더링/지연로딩, 텍스트 접근성 유지.
저사양 태블릿에서 초기 표시/페이지 전환/메모리를 기존 폰트 방식과 비교한 뒤 적용한다.
