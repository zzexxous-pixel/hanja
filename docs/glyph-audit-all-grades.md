# 8급–3급 1,000자 자형 대조

검토일: 2026-10-31. 기준: 사용자 제공 대한검정회 신출한자 훈음표 PDF 9개.
사용자 결정: 이전 8급 검토에서 관찰한 인쇄체/필기체의 서체 차이는 허용.

| 7급 | 20 | 20 | 완료 |

급수별 신출 목록 누락/추가 또는 중복 대응 없음. 현재 선택 SVG와 PDF 글자에서
명백한 구성요소 누락·치환을 발견하지 못했다. 새로운 자형 예외는 추가하지 않았다.
앞서 수정한 産도 PDF의 독립 글자와 대조했다.

이는 한 번의 육안 검토 결과이지 오류가 절대 없다는 보증이나 대한검정회 인증이 아니다.
픽셀·윤곽의 완전 일치가 아니라 아래 범위의 구조 대조다.

## 방법과 허용 범위

- PDF 내장 글꼴로 실제 글자 영역을 렌더링. Unicode 텍스트를 임의의 시스템 폰트로 바꿔 비교하지 않음.
- 총 12페이지. 11.1/12pt 본문 한자 1,000개를 bbox로 찾아 대응.
- 현재 scripts/strokes.mjs의 selectData/glyphSvg를 사용하므로 카드·쓰기에서 쓰는 敬/産 등 예외가 포함됨.
- 50자 이하씩 PDF 왼쪽/앱 오른쪽 비교 이미지 22장을 만들어 모두 시각적으로 대조(급수별 마지막 장은 50자 미만일 수 있음).
- PDF 제목 배경 도형이 일부 글자 영역과 겹치므로 비교용 사본에서 도형만 제거. 본문 글자는 유지, 원본 PDF는 수정하지 않음.
- 글자 외곽 여백을 잘라 확대하므로 원본 자폭·인쇄 크기의 정량 비교가 아님.
- 획의 굵기, 곡률, 기울기, 비례, 획 끝 및 점/짧은 획 표현 차이는 허용. 구성요소의 정체성과 누락 여부를 중심으로 확인.
- 溫(囚 내부), 硏(幵), 骨, 器, 德, 直, 者·著·都·諸, 靑 계열, 留·殺·食·飮·餘·戶 등은 확대해 재확인. 硏은 기존 동일 코드포인트 예외11획 데이터가 적용되어 있음. 이 표로 새 획수를 확정한 것은 아님.
- 六/車/不/樂/復/暴/宅 등 호환한자는 목록 대응에만 NFKC 사용. PDF의 실제 모양을 바꾸거나 앱의 문자 코드를 치환하지 않음.

## 검증하지 않은 사항

- 총획수·획순·획 방향: 이 훈음표만으로 공식값 확정 불가. 敬13획의 기존 별도 근거만 유지.
- 훈음 텍스트의 전수 교열, 복수 훈음의 허용 여부: 이번 자형 검토 범위 아님.
- 기관별 모든 필기 허용 규정: 이 인쇄 견본과의 대조만 수행.

## 검수 상태와 근거

`data/glyph-reference.json`에 9개 원본 파일명/SHA256/페이지수/대응수와 검토 기준을 기록했다.
글자별 shapeSourceId는 원본 급수를 가리키며 shapeSvgSha256은 실제 대조한 SVG를 고정한다.
검수페이지의 `reviewed`는 이 기준의 **완성 자형 1차 대조 완료**를 의미한다.
이후 SVG가 바뀌면 해시가 일치하지 않아 자형 상태가 다시 pending이 된다.

완성 자형은 1,000자 reviewed, 획순은 1,000자 pending. 공식 총획수 확인은 敬 한 글자만 유지.
자형 근거가 생겼다고 총획수 미확인을 불일치로 집계하지 않도록 보고서 계산을 수정했다.

원본 PDF/비교 캡처는 Git/Pages에 게시하지 않는다. 원본 전체를 재배포하지 않으며,
검수페이지에는 기존 앱 SVG와 결과/메타데이터만 제공한다.

## 재현(에이전트용, 앱 실행에 필요 없음)

선택 도구: PyMuPDF/Pillow. Node 개발 의존성 설치 후 저장소 루트에서:

```sh
python -m venv .venv
.venv/bin/pip install pymupdf Pillow
.venv/bin/python scripts/compare-pdf-glyphs.py /path/to/user-pdfs --output _audit/pdf-comparison
```

이미지/JSON은 Git 제외된 `_audit/`에 생성된다. 자동화는 목록 대응·렌더링까지만 수행하며,
육안 검토나 shapeReviewed 승인을 자동으로 수행하지 않는다.
